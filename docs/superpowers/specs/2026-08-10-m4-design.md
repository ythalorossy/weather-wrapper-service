# M4 — Polish & niche

**Status:** design approved, ready for plan
**Date:** 2026-08-10
**Owner:** backend + web

## Goal

Land three small, independent feature slices that round out the M2/M3 surface without introducing new upstream dependencies or architectural shifts:

1. **Radar station link** — make the existing `radarStationId` in `LocationMetadataResponse` clickable, pointing at the new radar.weather.gov station page.
2. **Area Forecast Discussion (AFD)** — surface the latest AFD product issued by the city's WFO, on a dedicated "Discussion" tab.
3. **Glossary tooltips** — small, hand-curated glossary; inline `<Glossary term="…">` wrapper shows a definition popover on hover/focus.

## Non-goals

- True closest-radar-station lookup (independent of WFO).
- Embedded radar map preview inside the app.
- Auto-detected glossary terms across the codebase.
- Standalone glossary page.
- Multi-office AFD picker; AFD is always for the office of the resolved city.
- Astronomy, AFD history, AFD search.

## Slice ordering

| # | Slice | Backend? | Frontend? | Why this order |
|---|---|---|---|---|
| 4.1 | Radar station link | no | yes | Pure frontend; trivial change on existing data. |
| 4.2 | AFD | yes | yes | Only backend-bearing slice; follows the same cache-aside pattern as M3 sun times. |
| 4.3 | Glossary tooltips | no | yes | Layered onto whatever text surfaces we have; no backend. |

Each slice is independently shippable as its own PR.

## 4.1 — Radar station link

### Change

<a
  href={`https://radar.weather.gov/?station=${office.radarStationId}`}

  rel="noopener noreferrer"

### Tests

## 4.2 — Area Forecast Discussion

### NWS API surface

Two endpoints, no auth, used sequentially:

1. `GET https://api.weather.gov/products/types/AFD` — JSON-LD list of recent AFD products. Each entry: `{ id, issuingOffice, issuanceTime, productCode, productName }`.
2. `GET https://api.weather.gov/products/{id}` — full product. The body is in `productText` (string with `\n\n` paragraph separators).

`issuingOffice` is the WFO id (e.g. `KLWX`), which matches `LocationMetadataResponse.office.officeId`.

### Domain (`weather-domain`)

- **New record:** `AfdProduct(String officeId, Instant issuanceTime, String body)`. Body already paragraph-trimmed; the adapter is responsible for parsing.
- **New port:** `AreaForecastDiscussionProvider`
  ```java
  Optional<AfdProduct> getLatest(String officeId);
  ```
- **New port:** `AfdCache`
  ```java
  Optional<AfdProduct> get(String key);
  void put(String key, AfdProduct value, Duration ttl);
  ```
  Default method `requireValidKey(key)` mirrors `SunTimesCache`.

### Infrastructure (`weather-infrastructure`)

- **`NwsAfdProvider implements AreaForecastDiscussionProvider`**:
  1. `GET /products/types/AFD` (with the same `User-Agent`/Accept headers used elsewhere — see existing NWS providers).
  2. Filter entries where `issuingOffice == officeId`.
  3. Sort by `issuanceTime` descending, take the first.
  4. `GET /products/{id}` to fetch `productText`.
  5. Return `new AfdProduct(officeId, issuanceTime, body)`. If the list is empty or the body fetch fails, return `Optional.empty()`.
- Wrapped in a `Timer.Sample` with `weather.provider.afd{outcome=success|failure}`.
- **`RedisAfdCache implements AfdCache`**: same JSON-on-strings + fail-open pattern as `RedisSunTimesCache`. Hit/miss counter `weather.cache.afd{result=hit|miss}`. Key: `afd:{officeId}`.

### Application (`weather-application`)

- **`GetAfdUseCase`** — resolves city via `LocationResolver` (existing), takes the office id off `LocationMetadataResult`, cache-aside on `AfdCache` with configured TTL. Returns `Optional<AfdProduct>`.
- Note: AFD depends on metadata. The use case resolves the office via the same `LocationResolver` path as `GetLocationMetadataUseCase`. If the office is unavailable (no NWS coverage, e.g. an overseas city), the use case returns `Optional.empty()`.

### API (`weather-api`)

- New endpoint: `GET /api/v1/weather/forecast/discussion?city=...`.
- Response DTO `DiscussionResponse(officeId, issuanceTime: Instant, body: String)`.
- Empty result returns 404 with the standard error envelope (matching how the existing metadata controller handles missing-office cases).
- OpenAPI annotations + an example value added.

### Configuration

- `application.yml`: `weather.afd.cache.ttl: 30m`.
- `WeatherProperties` gains `Afd.cache.ttl: Duration` (default `PT30M`).
- `UseCaseConfig` wires `AreaForecastDiscussionProvider`, `RedisAfdCache`, `GetAfdUseCase`.

### Metrics

- `weather_provider_afd_seconds` (Timer, `outcome=success|failure`) — wraps `NwsAfdProvider`.
- `weather_cache_afd_total` (Counter, `result=hit|miss`) — wraps `RedisAfdCache`.

### Frontend

- Extend `web/src/api/weather.ts`:
  ```ts
  export interface DiscussionResponse {
    officeId: string;
    issuanceTime: string; // ISO
    body: string;
  }
  export function useAfd(city: string | null) { ... }
  ```
  Stale time: 30 min (matches server cache TTL).
- New `DiscussionCard.tsx`:
  - Header: "Issued {issuanceTime} by {officeId}".
  - Body: `<div className="whitespace-pre-wrap text-sm leading-relaxed">{body}</div>` (preserves NWS's `\n\n` paragraph breaks; no markdown rendering).
  - Hidden when the query is pending; renders "No discussion available" when body is empty (e.g. overseas city).
- New `DiscussionTab.tsx` — a thin wrapper that owns `useAfd(city)` and renders `DiscussionCard`. Mounted inside `ForecastTabs` after Hourly. Tab order: **Daily · Hourly · Discussion**.

### Error handling

- NWS `/products/types/AFD` 5xx → `NwsAfdProvider` returns `Optional.empty()`. Use case propagates empty. UI shows "No discussion available" — no 502 to the user.
- Body fetch fails → same: empty result, friendly UI message.
- Cache fails open, recompute every request.
- Non-US cities (where `LocationResolver` returns a city but `LocationMetadataProvider` returns no office): use case short-circuits to `Optional.empty()`, controller 404s. UI's query returns 404 → tab renders "No discussion available".

### Tests (backend)

- `NwsAfdProviderTest` — uses MockWebServer (or the existing WireMock setup if present; otherwise MockWebServer is acceptable — verify against the existing test infra during implementation): a list endpoint returning 3 products (one matching `KLWX`, two others), verifies the matching one is selected; body endpoint returns a known paragraph; verifies the adapter produces the expected `AfdProduct`. Add a polar/no-coverage case.
- `GetAfdUseCaseTest` — cache hit (provider not called), miss (provider called, result cached), empty result (nothing cached).
- `RedisAfdCacheTest` (Testcontainers) — roundtrip, missing key, TTL expiry, prefix isolation (no collision with `afd:other:…`).
- `WeatherApiApplicationTest` — `GET /api/v1/weather/forecast/discussion` returns body for `Arlington VA`; returns 404 for a city whose WFO metadata is missing (existing pattern).

### Tests (frontend)

- `DiscussionCard.test.tsx` — renders body + header; renders "No discussion available" when body is empty.
- `ForecastTabs.test.tsx` (new) — verifies the third tab exists, is labelled "Discussion", and switches the panel content. Optional; can be deferred if no existing tabs test.

## 4.3 — Glossary tooltips

### Glossary data

`web/src/lib/glossary.json` — flat object keyed by lowercase term. Each entry has `{ "term": string, "definition": string }`. Starter set (~25 entries):

| Term | One-line definition |
|---|---|
| dBZ | Decibel relative to Z — radar reflectivity unit; higher values mean heavier precipitation. |
| CAPE | Convective Available Potential Energy — atmospheric instability; high values favor thunderstorms. |
| POP | Probability of Precipitation — chance a point sees measurable precipitation in the period. |
| virga | Precipitation that falls from a cloud but evaporates before reaching the ground. |
| wind chill | Perceived temperature accounting for heat loss from wind on exposed skin. |
| heat index | Perceived temperature accounting for humidity reducing sweat evaporation. |
| dewpoint | Temperature at which air becomes saturated; higher dewpoint = more moisture. |
| relative humidity | Water vapor in the air as a percentage of the maximum it can hold at that temperature. |
| wind shear | Change in wind speed or direction with height; affects storm intensity. |
| pressure | Atmospheric pressure, in millibars or inches of mercury. |
| visibility | How far one can see horizontally; reduced by fog, precipitation, haze. |
| gust | A brief spike in wind speed. |
| advisory | NWS alert for weather that causes inconvenience but isn't dangerous. |
| watch | NWS alert for conditions favorable for severe weather; be prepared. |
| warning | NWS alert for imminent or occurring severe weather; take action. |
| outlook | Extended-range assessment of expected conditions or hazards. |
| tornado | A violently rotating column of air touching the ground. |
| hurricane | A tropical cyclone with sustained winds ≥ 74 mph. |
| storm surge | Abnormal rise of water generated by a storm, over and above tide. |
| frostbite | Skin/tissue damage from extreme cold. |
| almanac | Historical climate averages used as a reference. |
| ceiling | Height of the lowest broken or overcast cloud layer. |
| obstruction | Anything blocking visibility near the surface (fog, haze, smoke). |
| drought | Extended period of below-normal precipitation. |
| haze | Suspension of fine particles that reduces visibility and adds a milky cast. |

(Definitions are short and paraphrased; final wording gets a brief review for accuracy during implementation. The exact list can grow over time.)

### Component

`web/src/components/Glossary.tsx`:

```tsx
import { useId, useState } from 'react';

interface Props {
  term: string; // case-insensitive key into glossary.json
  children?: React.ReactNode; // visible text; defaults to `term`
}

export function Glossary({ term, children }: Props) {
  const id = useId();
  const [open, setOpen] = useState(false);
  const entry = GLOSSARY[term.toLowerCase()];
  if (!entry) return <>{children ?? term}</>;
  return (
    <span className="relative inline-block">
      <button
        type="button"
        aria-describedby={open ? id : undefined}
        onFocus={() => setOpen(true)}
        onBlur={() => setOpen(false)}
        onMouseEnter={() => setOpen(true)}
        onMouseLeave={() => setOpen(false)}
        className="border-b border-dotted border-slate-400 cursor-help focus:outline-none focus:bg-sky-50"
      >
        {children ?? term}
      </button>
      {open && (
        <span
          id={id}
          role="tooltip"
          className="absolute left-0 top-full z-10 mt-1 w-64 rounded-md border border-slate-200 bg-white px-3 py-2 text-xs shadow-lg"
        >
          <strong className="block mb-1">{entry.term}</strong>
          {entry.definition}
        </span>
      )}
    </span>
  );
}
```

- The button + dotted underline is the visual affordance.
- `aria-describedby` only attached while open (the popover is `aria-hidden=false` via role=tooltip).
- Pure CSS positioning; no extra dependencies.
- Unknown terms render as plain text (fail open).

### Wiring

Wrap 2–3 terms in existing components:

| Component | Wrapped term(s) |
|---|---|
| `HourlyList.tsx` | "POP", "dBZ" (when shown in any shortForecast copy) |
| `AlertsBanner.tsx` | "watch", "warning" (in the head/severity text) |
| `CurrentConditionsCard.tsx` | "wind chill", "heat index" (in any labels) |

If a term isn't actually emitted by NWS in the rendered text (e.g. dBZ rarely appears in the public point forecast), the wrap is a no-op until/unless the data starts surfacing it. **No mass find-and-replace across all text fields** — only the small, deliberate spots where the term clearly appears.

### Tests

- One existing component test (e.g. `HourlyList.test.tsx` if added) — verifies the wrapper renders. Optional; can be deferred.
