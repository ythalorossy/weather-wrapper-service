# M3 — Multi-location + chart polish

**Status:** design approved, ready for plan
**Date:** 2026-08-09
**Owner:** backend + web

## Goal

Land three small, independent feature slices that round out the M2 surface
without introducing new upstream dependencies or architectural shifts:

1. **Saved locations** — pure-frontend `localStorage` persistence so users can
   jump between cities they've already searched for and return to their last
   city on a fresh visit.
2. **Sunrise/sunset** — wire the existing `SunTimes` domain record to a local
   solar-position calculator and surface the result on the metadata endpoint
   and the metadata strip in the UI.
3. **Hourly temperature chart** — a hand-rolled SVG line chart embedded in the
   Hourly tab, above the existing `HourlyList`.

## Non-goals

- Multi-pane dashboard rendering several cities side-by-side.
- Reorder/import/export UI for saved locations.
- Astronomical data beyond sunrise/sunset (no moon phase, civil twilight, etc.).
- New charting library.
- New NWS upstream calls.
- Server-side saved-location state.

## Slice ordering

| # | Slice | Backend? | Frontend? | Why this order |
|---|---|---|---|---|
| 3.1 | Saved locations | no | yes | Pure frontend; unblocks the visual testing of 3.2 and 3.3. |
| 3.2 | Sunrise/sunset | yes | yes | Only backend-bearing slice; rides on the existing metadata use case. |
| 3.3 | Hourly temperature chart | no | yes | Self-contained polish; lands on top of stable data hooks. |

Each slice is independently shippable as its own PR.

## 3.1 — Saved locations

### Data model (frontend only)

| localStorage key | Value | Purpose |
|---|---|---|
| `weather-wrapper-service:saved-cities:v1` | `string[]` (JSON) | The set of saved city strings. |
| `weather-wrapper-service:last-city:v1` | `string` | The last city searched; restored on mount. |

Version suffix (`v1`) leaves room for future migrations. Display names
("Arlington, VA, United States") come back from the server's
`resolvedLocation.displayName` — we never persist them.

### New files (frontend)

| Path | Purpose |
|---|---|
| `web/src/lib/savedLocations.ts` | Pure helpers: `load()`, `save()`, `add()`, `remove()`, `isSaved()`. Synchronous. SSR-safe (`typeof window` guard). Swallows quota/private-mode errors with a console warning. |
| `web/src/hooks/useSavedLocations.ts` | `useSyncExternalStore`-based hook. Subscribes to native `storage` events for cross-tab sync and a local pub-sub for same-tab sync. |
| `web/src/hooks/useLastCity.ts` | Returns the last city on mount, writes when the current city changes. |
| `web/src/components/SavedLocationsPills.tsx` | Horizontal pill row above the search form. Renders only when ≥1 saved city. Each pill: city name + × remove. Active pill: bold + sky underline. Click → `onSelect(city)`. |
| `web/src/components/SaveLocationButton.tsx` | Star toggle on the forecast header. Filled ★ saved / outline ☆ unsaved. Renders only after `daily.data` resolves (don't save failed lookups). |

### App.tsx wiring

- `const [city, setCity] = useState<string | null>(loadLastCity())` initial value.
- `useLastCity(city)` writes to storage on change.
- `useSavedLocations()` owns the saved set; `SaveLocationButton` and `SavedLocationsPills` share it.

### Error handling

- localStorage unavailable → helpers swallow, console.warn. UI degrades to "no saved locations" with no user-visible error.
- Dedupe on save: case-insensitive, trimmed. `'Arlington, VA'` twice → one entry.

### Tests

- `web/src/lib/savedLocations.test.ts` — add / remove / isSaved / dedupe / case-insensitive / throws-on-write → swallow path.
- `web/src/hooks/useSavedLocations.test.ts` — pub-sub broadcast across subscribers.

## 3.2 — Sunrise/sunset

### Library

`net.e175.klaus:solarpositioning` (MIT). Pin via new parent-pom property
`solarpositioning.version` (latest 4.x stable). The library provides
`SunriseSunsetCalculator.forHorizon(date, lat, lon, SUNRISE_SUNSET_ZENITH_OFFICIAL)` —
the same math NOAA's published solar calculator uses, accurate to <1 minute.

### Domain (`weather-domain`)

- **`SunTimes`** — already exists, no change.
- **New port:** `SunTimesProvider`
  ```java
  Optional<SunTimes> getSunTimes(Location location, LocalDate date);
  ```
- **New port:** `SunTimesCache`
  ```java
  Optional<SunTimes> get(String key);
  void put(String key, SunTimes value, Duration ttl);
  ```

### Infrastructure (`weather-infrastructure`)

- **`ComputedSunTimesProvider implements SunTimesProvider`** — wraps
  `SunriseSunsetCalculator`. Deterministic for given inputs
  (location + date); converts the calculator's `ZonedDateTime` result to
  `Instant` via `location.timezoneId()` (already on `Location`).
- **`RedisSunTimesCache implements SunTimesCache`** — JSON-encoded.
  Cache key format: `sun:{lat:.2f},{lon:.2f}:{date-ISO}` (date at the
  application layer). Fails open on Redis error (logged warn), per the
  existing pattern in `RedisLocationCache`.

### Application (`weather-application`)

- **`GetSunTimesUseCase`** — resolves city via the shared `LocationResolver`,
  then cache-aside on `SunTimesCache`. On miss, calls `SunTimesProvider.getSunTimes(location, today)`,
  stores with 48h TTL. Returns `Optional<SunTimes>` (missing is a valid state).

### API (`weather-api`)

- Extend `LocationMetadataResponse` with a nested `SunView`:
  ```java
  public record SunView(
      LocalDate date,             // ISO date in location timezone
      String sunriseLocal,        // "HH:mm" in location timezone
      String sunsetLocal,         // "HH:mm" in location timezone
      long dayLengthSeconds       // for "13h 52m" without re-formatting
  ) {}
  ```
- `GetLocationMetadataUseCase` returns `LocationMetadataResult(office, Optional<SunTimes>)`.
- `WeatherController.getMetadata(...)` builds the response; sun field omitted if `Optional.empty()`.
- OpenAPI annotations + example values added.

### Configuration

- `application.yml`: `weather.sun.cache.ttl: 48h`.
- `WeatherProperties` gains `Sun.cache.ttl: Duration` (default 48h).
- `UseCaseConfig` wires `SunTimesProvider` + `SunTimesCache` + `GetSunTimesUseCase`.

### Metrics

- `weather_provider_sun_seconds` (Timer, `outcome=success|failure`) — wraps `ComputedSunTimesProvider`.
- `weather_cache_sun_total` (Counter, `result=hit|miss`) — wraps `RedisSunTimesCache`.
- `service=weather-wrapper-service` tag via existing `MetricsConfig.commonTags`.

### Frontend

- Extend `LocationMetadataResponse` type with `sun?: SunView`.
- New `SunTimesCard` — small element next to / under `MetadataBar`. Renders:
  `☀ 6:42 ↑ · 19:34 ↓ · 13h 52m` (using `sunriseLocal` / `sunsetLocal` / `dayLengthSeconds`).
- Hidden when `metadata.data.sun` is undefined.
- `useLocationMetadata` staleTime stays 24h (sun bundled in same response).

### Error handling

- Calculator throws (polar region, arithmetic edge) → `SunTimesProvider` catches,
  returns `Optional.empty()`. Cache stores nothing. UI hides the card. No 502.
- Cache failure → fails open, recompute every request (slow but correct).

### Tests (backend)

- `ComputedSunTimesProviderTest` — known fixtures: Arlington VA, Honolulu HI, Reykjavik IS (polar edge — no sunrise/sunset).
- `GetSunTimesUseCaseTest` — cache hit / miss / write-through / cache-fails-open.
- `RedisSunTimesCacheTest` (Testcontainers) — roundtrip, missing key, TTL expiry, prefix isolation.
- `WeatherApiApplicationTest` — metadata response includes `sun` for known cities; sun omitted when provider returns empty.

### Tests (frontend)

- `SunTimesCard.test.tsx` — renders all fields; renders nothing when `sun` undefined.

## 3.3 — Hourly temperature chart

### Placement

Inside the Hourly tab of `ForecastTabs.tsx`. SVG sits above the existing
`HourlyList`, both wrapped in a single `<section>`.

### Component

`web/src/components/HourlyChart.tsx`

```ts
interface Props {
  data: HourlyWeatherResponse;
  rowRefs: RefObject<(HTMLLIElement | null)[]>;
  hours?: number; // default 48
}
```

### SVG structure (no library, ~140 LOC)

- `viewBox="0 0 800 200"`, `preserveAspectRatio="none"`, `role="img"` + descriptive `aria-label`.
- **X axis:** time, even spacing across `hours`.
- **Y axis:** temperature, padded ±2 °F above min/max of the window.
- **Day/night bands:** rectangles drawn first (behind the line). Day = `period.daytime` flag + intersected with sunrise/sunset from `metadata.data.sun`. Sky-50 for daytime, slate-700 (alpha) for night.
- **Line:** single `<path d="M…L…">` from `{x, y}` points. `vector-effect="non-scaling-stroke"`.
- **Hover dot:** invisible `<rect>` per hour covers its X slice. `onMouseMove` reveals a 4 px dot + `<text>` tooltip (`time · temp`, browser locale).
- **Click → scroll:** `rowRefs.current[i]?.scrollIntoView({ behavior: 'smooth', block: 'center' })`. Briefly highlights that list row (sky-50 ring for 1.5 s).

### State

All local to the component (`useState` for hover index + highlight index).

### Error handling

- `periods.length === 0` → render nothing (don't crash the Hourly tab).
- `metadata.data?.sun` undefined → skip day/night bands, neutral background.

### Accessibility

- `<svg role="img" aria-label="Temperature from 32°F at 3pm to 41°F at 6pm">`
- Tooltip is `aria-hidden`; chart purpose is conveyed by the label + the sibling `<HourlyList>`.

### Tests

- `HourlyChart.test.tsx` — renders 48 path segments for 48 hours; empty data renders nothing; click on hour 5 calls `scrollIntoView`; missing `sun` doesn't crash.
- Snapshot test for one happy-path render.
